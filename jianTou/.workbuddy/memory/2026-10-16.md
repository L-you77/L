## 第三轮调整（19:56）—— 闪红与"同时结算"
- 用户明确要求：**踩中和被敌人扎到必须在同一帧一起结算**（受伤和伤害同时进行），不要"踩踏免伤"。

  → player.tscn 的 HurtBox 碰撞盒恢复成 6x6 居中（我上轮改成 5x5 上移 1.5px 的做法撤掉）。
- **关键**：`StompInvincibleTime` 默认 0.3 → 0。踩踏成功原本会给 0.3s 无敌帧，
  如果敌人的 HitBox 在同一帧稍晚触发，这 0.3s 会把伤害挡掉 → 表现为"有时掉血有时不掉"。
  现在踩踏不额外给无敌帧，两边必定同时结算。想改成"踩敌人安全"就把这个值调回 0.2~0.3。
- Player 受伤也闪红：新增 `HurtColor` / `HurtFlashTime`（受击表现组），
  `UpdateBlink()` 改名 `UpdateSpriteTint()`，优先级：刚受伤闪红 → 无敌帧半透明闪烁 → 白色。
- 敌人死亡表现改为**闪红 → 立即销毁**：删掉 DeathHop / DeathBounceSpeed / DeathGravity / DeathFadeTime /
  HandleDeathMotion / FadeOutAndFree（原来的"弹一下 + 淡出 0.35s"），
  改用 `DeathFlashTime`（默认 0.08s）+ `QueueFreeOnDeath`，死亡瞬间 Velocity=0 定格并立即 UpdateSpriteTint 变红。

## 第四轮修复（20:55）—— 敌人死亡后不销毁
- **根因（重要教训）**：`EnemyBase.Die()` 开头写的是 `if (!IsAlive) return;`，
  而 `IsAlive => Health > 0`，但 `TakeDamage` 里是**先把血量减到 0、再调 `Die()`**，
  于是 `Die()` 每次都在第一行直接 return —— 闪红、关碰撞、销毁全都没执行，
  敌人只是被 `_PhysicsProcess` 的 `if (!IsAlive) return` 定格在原地，永远不消失。
- 修法：新增独立标记 `public bool IsDying { get; private set; }` 作为"是否已进入死亡流程"的判据，
  `Die()` 用 `if (IsDying) return;`。**凡是"先改状态、后调方法"的流程，幂等判断都不能用状态推导量。**
- 销毁时机从 `async void` + `GetTree().CreateTimer` 改成**物理帧倒计时** `_deathTimer`，
  在 `_PhysicsProcess` 里自减到 0 就 `QueueFree()`。不再依赖 async 续体/场景树计时器，行为确定。
- 同理把 `Player.Die()` 也从 async 改成物理帧倒计时（`_deathTimer` + `FinishDeath()`），
  `FinishDeath()` 里 `ReloadCurrentScene()` 返回非 Ok 时兜底走 `Respawn()`，避免卡在死亡状态。
  全项目已无 `async void` / `ToSignal`。
